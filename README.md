# Solar Business Performance — Sales & Pipeline Dashboard

แอปบันทึก/ติดตามโครงการที่กำลังเสนอขาย (Sales Pipeline) สำหรับงานขาย Solar / Battery
ไฟล์เดียวจบ เปิดได้ทั้งบนคอมและมือถือ บันทึกข้อมูลลงเครื่อง + ซิงก์ Google Sheet ได้

## ไฟล์ในโฟลเดอร์
- `index.html` — ตัวแอป (เปิดด้วยเบราว์เซอร์ได้เลย หรือ host ขึ้น GitHub Pages)
- `customers.js` — ฐานลูกค้า 4,768 ราย ที่แอปโหลดมาทำ autocomplete (**ต้องวางคู่กับ index.html เสมอ**)
- `sales_history.js` — ข้อมูลยอดขายย้อนหลัง 2559–2569 สำหรับกราฟและ Drill-down
- `pi_items.js` — รายการสินค้าในแต่ละ PI สร้างจากไฟล์ Report_sale
- `สรุปยอดขาย 2559-2569  สรุปยอดขาย.xlsx` — ไฟล์ต้นทางยอดขายย้อนหลัง
- `scripts/build_sales_history.py` — สร้าง `sales_history.js` ใหม่เมื่อแก้ไข/เพิ่มชีตปีใหม่
- `scripts/build_pi_items.py` — สร้าง `pi_items.js` ใหม่เมื่อเปลี่ยนไฟล์ Report_sale

- `vendor/pdf.min.js`, `vendor/pdf.worker.min.js` — ตัวอ่าน PDF (pdf.js 3.11.174 ของ Mozilla, สัญญาอนุญาต Apache 2.0) ใช้ตอนนำเข้ารายงานลูกหนี้ที่เป็น PDF (**ต้องวางคู่กับ index.html และอัปโหลดขึ้นเว็บด้วย**)
- `app-icon.svg` — ต้นฉบับไอคอนแอป
- `scripts/build_report_latest.py` — สร้าง `report_latest.js` จาก Report_sale ล่าสุด (รันหลังวางไฟล์รายงานใหม่ทุกครั้ง)
- `report_latest.js` — รายงานล่าสุดที่ห่อให้แอปอ่านเองได้ (สร้างโดยสคริปต์ · **ห้ามขึ้น GitHub**)
- `README.md` — ไฟล์นี้

## นำเข้าข้อมูล — แยกช่องตามชนิดไฟล์ (เพิ่ม 24 พ.ย. 2026)
กดปุ่ม **"นำเข้าข้อมูล"** บนแถบเครื่องมือ (มือถือ: เพิ่มเติม › นำเข้าข้อมูล) จะเห็น 4 ช่อง แต่ละช่องบอกไฟล์ที่ใช้ และข้อมูลชุดล่าสุดที่อยู่ในแอป

| ช่อง | ไฟล์ที่ใช้ | ใช้ในหน้า |
|---|---|---|
| ใบเสนอราคา / PI | `Report_sale_YYYYMMDD.xls` จาก ERP | ภาพรวม · ตาราง · Kanban |
| ยอดขายจริง | `สรุปยอดขาย แบบแจกแจง .xlsx` จากบัญชี | ยอดขาย · ผู้บริหาร |
| ลูกหนี้ค้างรับ | `รายงานลูกหนี้ค้างรับ วว-ดด-ปปปป .pdf` (หรือ Excel) | ลูกหนี้ · ผู้บริหาร |
| เคลมสินค้า | ไฟล์เคลมสินค้า `.xlsx` | เคลมสินค้า · ผู้บริหาร |

- กด "เลือกไฟล์" ในช่องนั้น หรือลากไฟล์มาวางที่ช่อง (บนคอม) · วางไฟล์ผิดชนิดช่องจะไม่รับและแจ้งเตือน
- สีของแถบสถานะ: เขียว = ข้อมูลไม่เกิน 7 วัน · เหลือง = เก่ากว่า 7 วัน · เทา = ยังไม่เคยนำเข้า

## งานเดียวกันที่เสนอหลายลูกค้า — นับใน Pipeline ครั้งเดียว (เพิ่ม 23 พ.ย. 2026)
- **อัตโนมัติ**: ใบเสนอราคาที่ยังไม่ได้งาน (NEW PI / 30% / 50% / 90%) ที่ต่างลูกค้า แต่รายการสินค้า จำนวน และมูลค่าตรงกันทุกตัว ถือเป็นงานเดียวกัน
- **ตั้งเอง**: เปิดดีล › ช่อง "งานเดียวกันที่เสนอหลายลูกค้า" › ใส่ **รหัสงานร่วม** เดียวกันในทุกดีลของงานนั้น (ใช้เมื่อราคาแต่ละรายไม่เท่ากัน)
- ในกลุ่มนับเฉพาะดีลเดียว: โอกาสสูงสุด → PI ล่าสุด → มูลค่าสูงสุด · ดีลที่เหลือขึ้นป้าย "งานเดียวกัน · ไม่นับซ้ำ" และมูลค่าไม่ถูกรวมใน Pipeline / ถ่วงน้ำหนัก / Forecast
- ถ้าแอปจับคู่ผิด กด **"แยกนับดีลนี้"** ในดีลนั้น
- ดีลที่ได้ PO แล้ว (PO IN / PO WIN) ไม่ถูกจับคู่อัตโนมัติ เพราะสินค้าและราคาเดียวกันที่ขายได้จริงสองรายคือสองงาน
- การ์ด "มูลค่า Pipeline" บอกจำนวนดีลและมูลค่าที่ไม่ได้นับซ้ำ

## นำเข้าใบเสนอราคา (Report_sale) — สำคัญที่สุด
ไฟล์ `Report_sale_YYYYMMDD.xls` ที่ export จากโปรแกรมบริษัท = ดีลทั้งหมดของคุณพร้อมสถานะ
- กดปุ่ม **"นำเข้า PI"** ในแถบเครื่องมือ → เลือกไฟล์ .xls → แอปสร้าง/อัปเดตโครงการให้อัตโนมัติ
- map Status → สถานะ: `NEW PI`→เสนอราคา · `30%`→เสนอราคา · `50%/90%`→เจรจา · `PO WIN/PO IN`→ปิดได้ · `LOST`→หลุด (ใช้ % เป็นค่าโอกาสปิด)
- ลูกค้าลิงก์กับฐาน customers.js (เบอร์/TaxID/ที่อยู่) · สินค้าแมทเป็นแบรนด์ (SE/P###→SolarEdge, LP→Leapton, SPPM→Solar PPM, LR→Longi, Atrix→Sunwoda, BluE-S→KSTAR, ST→Schutten, HD→HUIDA, JKM→Jinko, JAM→JA Solar, TP→Talesun, EE2→Ekarat, "STP /SB "→SMA)
- **กันซ้ำด้วยเลข PI** (ตัด -R0/-R1 ออก) → export ไฟล์ใหม่แล้วนำเข้าทับ = อัปเดตดีลเดิม ไม่สร้างซ้ำ
- เก็บ piRef/piStatus/piDate ไว้ในโน้ตของโครงการ

## ช่องลูกค้า (autocomplete)
- พิมพ์ชื่อในช่อง "ลูกค้า / หน่วยงาน" → เลือกจากฐาน → เติม เบอร์/อีเมล/TaxID/ที่อยู่ ให้อัตโนมัติ
- ปุ่มสลับ **"ลูกค้าของฉัน" (ค่าเริ่มต้น) / "ทั้งหมด"** — ของคุณขึ้นก่อนเสมอ, ของเซลล์คนอื่นมีป้ายชื่อเซลล์กำกับ
- ข้อมูลลูกค้าจะถูกเก็บไปกับโครงการ (custTel/custEmail/custTaxId/custAddress) ใช้ทำใบเสนอราคาต่อได้
- ถ้าไม่มี `customers.js` แอปยังทำงานได้ปกติ แค่พิมพ์ชื่อลูกค้าเอง (ไม่มี autocomplete)
- อัปเดตฐานลูกค้า: รัน `python3 clean_customers.py` แล้วแปลงเป็น customers.js ใหม่

## วิธีใช้งานเบื้องต้น
1. เปิด `index.html` ด้วย Chrome / Safari
2. กด **+ เพิ่มโครงการ** กรอกข้อมูล → บันทึก
3. สลับมุมมองด้วยแท็บด้านบน:
   - **ภาพรวม** — KPI: จำนวนโครงการในมือ, มูลค่า Pipeline, มูลค่าถ่วงน้ำหนัก %, ปิดได้แล้ว + funnel ตามสถานะ + มูลค่าตามสินค้า
   - **ตาราง** — ค้นหา / กรอง / เรียงทุกคอลัมน์ คลิกแถวเพื่อแก้ไข
   - **Kanban** — เห็น pipeline เป็นภาพ ลากการ์ดข้ามคอลัมน์ หรือแตะปุ่ม ←/→ เพื่อเลื่อนสถานะ (ใช้บนมือถือได้)
4. กด **Excel** เพื่อ export เป็นไฟล์ .xls สรุป (ลำดับ · วันเดือนปี · เลข PI · ชื่อบริษัท · จำนวนเงิน + ยอดรวมล่างสุด) — **ส่งออกตามตัวกรองที่เลือก** เช่น กดชิป PO IN ก่อนแล้วค่อยกด Excel จะได้เฉพาะ PO IN พร้อมยอดรวม

ข้อมูลเก็บในเครื่อง (localStorage) ใช้งานได้แม้ไม่มีเน็ต

## สถานะโครงการ (เกณฑ์ที่ใช้จริง กำหนด 23 พ.ย. 2026)
| สถานะ | ความหมาย | % ถ่วงน้ำหนัก |
|---|---|---|
| NEW PI | ใบเสนอราคาใหม่ ยังไม่จัดสถานะ | 30% |
| 30% | ลูกค้าขอราคา | 30% |
| 50% | งานประมูล | 50% |
| 90% | คุยราคาจบแล้ว | 90% |
| PO IN | ได้มัดจำ/PO แล้ว (รวมงานทยอยรับ) | 100% |
| PO WIN | เปิดใบกำกับภาษีครบแล้ว | 100% |
| LOST | ไม่ได้งาน | 0% |

- NEW PI เดิมถ่วงน้ำหนัก 50% เท่างานประมูล ทำให้ Pipeline ถ่วงน้ำหนักสูงเกินจริง จึงลดเป็น 30% ดีล NEW PI ที่เก็บไว้ที่ 50% จะถูกปรับเป็น 30% เองตอนเปิดแอป
- NEW PI ที่ออกมาเกิน 7 วัน จะขึ้นป้าย **"ยังไม่จัดสถานะ N วัน"** และนับในการ์ด "ยังไม่จัดสถานะ" ให้เข้าไปจัดเป็น 30% / 50% / 90%
- เลื่อนสถานะแล้ว % โอกาสปิดจะปรับตามเกณฑ์ให้อัตโนมัติ (ทั้งดีลใหม่และดีลเดิม) แต่แก้เองได้

## รอส่ง / ค้างรับ (PO IN ที่ทยอยรับ)
- ดีล PO IN ไม่อยู่ในรายการโทร/ติดตาม แต่จะอยู่ในรายการ **"รอส่ง / ค้างรับ"** บนหน้าภาพรวม จนกว่ายอดค้างรับจะเป็น 0
- ไฟล์ Report_sale ไม่มีข้อมูลใบส่งสินค้า จึงต้องใส่ยอดค้างรับเอง: เปิดดีล › ช่อง "ค้างรับ / รอส่ง" › วาง **Comment 1 ของใบส่งสินค้า** (รอบละบรรทัด) › กด "บันทึกยอดค้างรับ"
- รูปแบบที่อ่านได้: `YYYYMMDD-001 รับรอบที่ N รับจำนวน X/4800 แผง คงเหลือ ค้างรับ Y แผง` หรือแบบย่อ `ค้างรับ 868/4800 แผง` · ถ้าวางหลายรอบ แอปใช้รอบที่มากที่สุด
- ดีล PO IN ที่ยังไม่ได้ใส่ยอด จะอยู่ในรายการพร้อมป้าย "ยังไม่ได้ใส่ยอดค้างรับ" · ใส่ยอดค้างรับ 0 = ส่งครบแล้ว ออกจากรายการ
- ยอดค้างรับเก็บในช่อง `delivery` ของดีล และซิงก์ขึ้น Sheet (ต้องใช้ `AppsScript.gs` รุ่น 23 พ.ย. ขึ้นไป)

## ยอดขายย้อนหลัง
- หน้า **ภาพรวม** มีกราฟครบทุกปี 2559–2569 และเลื่อนแนวนอนได้เมื่อหน้าจอแคบ

- Top Customers สลับอันดับได้ตามยอดขายหรือจำนวนบิล
- ค้นหาลูกค้าจากข้อมูลทุกปี → ดูยอดสะสมและประวัติรายปี → กดบิลเพื่อดูสินค้า จำนวน และยอดขาย
- Top สินค้าสลับดูได้ตามแบรนด์ หมวดสินค้า หรือ SKU
- เมนูตั้งค่ามีปุ่มสำรองและกู้คืนข้อมูลแบบ JSON ซึ่งเก็บรายละเอียดโครงการ สินค้า และประวัติกิจกรรมครบถ้วน
- หน้า Dashboard มีศูนย์งานวันนี้ สถานะวันที่ข้อมูล และยอดขายจริงเทียบเป้ารายเดือน
- ช่องค้นหาหลักรองรับเลข PI และเปิดรายละเอียดพร้อมรายการสินค้าได้โดยตรง
- ปีปัจจุบันแสดงป้าย `YTD` เพื่อไม่ให้เปรียบเทียบกับปีเต็มโดยไม่ตั้งใจ
- **อัปเดตยอดขาย (แนะนำ):** กดปุ่ม **"นำเข้ายอดขาย"** บนแถบเครื่องมือ → เลือกไฟล์ `สรุปยอดขาย ….xlsx` → แอปอ่าน `.xlsx` ในเครื่อง (ไม่ส่งออกไปไหน ไม่ต้องใช้ไลบรารีภายนอก) จัดบิลเข้าปี พ.ศ. ตามวันที่ใบสำคัญ แล้วเก็บลง localStorage ทับข้อมูลเดิม — ไม่ต้องเปิด terminal
- ทางเลือกเดิม (ผ่าน terminal): เพิ่ม/แก้ชีตในไฟล์ Excel แล้วรัน `python3 scripts/build_sales_history.py` เพื่อสร้าง `sales_history.js` ใหม่ (ใช้เมื่ออยากบันเดิลข้อมูลไปกับ index.html)

## เชื่อมต่อ Google Sheet (ใช้บนมือถือ + สำรองข้อมูล)
ทำครั้งเดียว:
1. สร้าง Google Sheet ใหม่ → เมนู **ส่วนขยาย › Apps Script**
2. ลบโค้ดเดิม วางโค้ดจาก `AppsScript.gs` → บันทึก
3. **Deploy › New deployment › Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
4. คัดลอก Web app URL (ลงท้าย `/exec`)
5. ในแอปกดปุ่ม **เชื่อมต่อ Sheet** (มุมขวาบน) → วาง URL → บันทึก & ซิงก์

หลังจากนั้นทุกครั้งที่เพิ่ม/แก้/ลบ ข้อมูลจะซิงก์ขึ้น Sheet อัตโนมัติ
เปิดแอปจากเครื่องอื่น/มือถือ แล้วใส่ URL เดียวกัน → กด "บันทึก & ซิงก์" แอปจะดึงข้อมูลจาก Sheet ลงมาให้เอง

### การป้องกันข้อมูล (เพิ่ม 19 พ.ย. 2026)
- **รหัสซิงก์**: ตั้งค่า `TOKEN` บรรทัดบนของ `AppsScript.gs` แล้วใส่รหัสเดียวกันในแอป (หน้าตั้งค่า ช่อง "รหัสซิงก์") ทุกเครื่อง — คนที่ได้ URL ไปแต่ไม่มีรหัสจะอ่าน/เขียนไม่ได้ · เว้นว่าง = ไม่ตรวจรหัส
- **เชื่อม Sheet จากเครื่องใหม่**: ถ้า Sheet มีข้อมูลอยู่แล้ว แอปจะดึงลงมา ไม่ส่งข้อมูลเครื่องนี้ขึ้นทับเอง · ถ้าทั้งสองฝั่งมีข้อมูล แอปจะถามก่อน
- **สำรองอัตโนมัติใน Sheet**: ก่อนเขียนทับครั้งแรกของแต่ละวัน สคริปต์คัดลอกชีตเดิมเก็บเป็นชีตซ่อนชื่อ `Backup_PileLine_<วันที่>` / `Backup_AppData_<วันที่>` ย้อนหลัง 7 วัน (ดูได้ที่ คลิกขวาแถบชีต › Show hidden sheets)
- **งานที่แก้ตอนออฟไลน์**: ป้ายซิงก์จะขึ้น "รอส่งขึ้น Sheet" และเปิดแอปครั้งถัดไปจะส่งขึ้นก่อน ไม่ดึง Sheet มาทับ
- **แก้จากสองเครื่อง (เพิ่ม 21 พ.ย. 2026)**: Sheet มีเลขรุ่นข้อมูล ทุกครั้งที่บันทึกเลขจะเพิ่ม ถ้าเครื่องนี้จะส่งข้อมูลขึ้น แต่ Sheet ถูกแก้จากเครื่องอื่นไปแล้ว หลังบ้านจะไม่เขียนทับ ป้ายซิงก์ขึ้น "ข้อมูลชนกัน" และแอปถามให้เลือกว่าจะใช้ข้อมูลจาก Sheet หรือของเครื่องนี้ (ต้องใช้ `AppsScript.gs` รุ่น 21 พ.ย. ขึ้นไป)
- **ข้อจำกัดที่ยังอยู่**: เมื่อข้อมูลชนกัน ต้องเลือกชุดใดชุดหนึ่งทั้งชุด แอปยังรวมการแก้รายดีลจากสองเครื่องเข้าด้วยกันไม่ได้ และข้อมูลลูกหนี้/เคลมยังไม่มีการตรวจชนกันแบบนี้
- แก้ `AppsScript.gs` แล้วต้อง Deploy › Manage deployments › New version ทุกครั้ง ไม่งั้นหลังบ้านยังเป็นรุ่นเดิม
- **รหัสซิงก์เปิดใช้แล้วตั้งแต่ 21 พ.ย. 2026**: รหัสจริงอยู่ในบรรทัด `var TOKEN` ของโค้ดใน Apps Script ของ Sheet เท่านั้น ไฟล์ `AppsScript.gs` ในโฟลเดอร์นี้และบน GitHub ตั้งใจเว้น `TOKEN` ว่างไว้ เพราะ repo เป็นสาธารณะ — **เวลาวางโค้ดรุ่นใหม่ทับใน Apps Script ต้องใส่รหัสเดิมกลับที่บรรทัด `var TOKEN` ก่อน deploy ทุกครั้ง** ไม่งั้นหลังบ้านจะกลับไปเปิดให้ทุกคนที่มี URL

> ถ้าอัปเดตจากเวอร์ชันเดิมและต้องการซิงก์ **ประวัติกิจกรรม (Activity History)** ข้ามเครื่อง
> ให้นำ `AppsScript.gs` เวอร์ชันล่าสุดไปวางทับ แล้ว Deploy › Manage deployments › New version หนึ่งครั้ง
